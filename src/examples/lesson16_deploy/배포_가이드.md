# [16차시] 배포와 총정리 가이드

## 1. 배포의 개념

넥사크로 소스(.xfdl, .xjs, .xadl)는 그대로 실행되지 않는다.
**Generate(변환)** 과정을 거쳐 브라우저가 실행할 수 있는 JavaScript 로 변환된 후 웹서버에 올라간다.

```
소스 (.xfdl / .xjs / .xadl)
   │  Generate (Nexacro Studio)
   ▼
변환 결과 (.xfdl.js / .xjs.js + index.html)
   │  웹서버 복사 (Tomcat, nginx, IIS ...)
   ▼
사용자 브라우저에서 실행
```

## 2. Nexacro Studio 에서 배포하기

1. 메뉴 **Build > Generate Application** (단축키 가능)
   - 출력 경로: 프로젝트 설정의 Generate Path 확인
2. **Deploy > Application Deploy** 또는 출력 폴더를 웹서버 문서 루트에 복사
3. 브라우저에서 `http://서버주소/프로젝트명/index.html` 접속 확인

## 3. 업데이트와 캐시

- 넥사크로 런타임은 변환된 파일을 **로컬 캐시**에 저장한다.
- 재배포 후 화면이 안 바뀌면 → 캐시 문제일 가능성이 높다.
- 운영 환경에서는 버전 관리(서비스 버전 갱신)로 캐시를 무효화한다.
- 개발 중에는 브라우저 강력 새로고침(Ctrl+Shift+R) 또는 캐시 삭제로 확인.

## 4. 자주 하는 실수 총정리 (코드 리뷰 체크리스트)

| # | 실수 | 증상 | 원인/해결 |
|---|------|------|-----------|
| 1 | `set_xxx()` 대신 직접 대입 (`obj.text = "..."`) | 화면이 안 바뀜 | 실행 시점 속성 변경은 반드시 setter 사용 |
| 2 | 콜백 함수 이름 오타 | 조회 버튼이 "아무 반응 없음" | transaction 6번째 인자는 **문자열** — 오타여도 에러가 안 난다. 출력창 trace 로 확인 |
| 3 | Dataset 행이 0개인데 바인딩 기대 | 상세폼에 입력해도 값이 안 들어감 | BindItem 은 "현재행"에 연결됨 — `addRow()` 로 빈 행을 만들어야 동작 |
| 4 | 저장 후 재조회 누락 | 사번이 빈 채로 남음, rowtype 이 안 풀림 | 저장 성공 콜백에서 반드시 재조회 |
| 5 | deleteRow 가 바로 지워진다고 착각 | 삭제했는데 저장하면 또 지워달라고 함 | Dataset 은 삭제분을 기억한다 — `:U` 전송으로 서버 반영 후 재조회 |
| 6 | 팝업 close() 에 객체 전달 | 부모 콜백에서 undefined | close() 는 문자열만 — JSON.stringify / parse 사용 |
| 7 | 통신 비동기를 동기처럼 코딩 | transaction 다음 줄에서 결과 사용 → 빈 값 | 결과 처리는 반드시 콜백 안에서 |
| 8 | Calendar value 형식 혼동 | 날짜 비교/저장 오류 | value 는 항상 `yyyyMMdd` 문자열 (표시 형식과 별개) |
